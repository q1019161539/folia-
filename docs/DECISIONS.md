# 关键设计决定

## 小步整理与扫描诊断（2026-10-06）

只读扫描诊断独立为 automation_runtime.py，主编排保持原扫描、基线、入队和串行规则。异常只在接口记录类型，完整 traceback 保留在日志，避免潜在凭据出现在诊断响应。该状态明确为进程内临时信息，不用它替代 SQLite 任务状态或宣称跨进程互斥。整理源码基线不启用投稿、不改变封面和时间轴算法；后续拆分按模块逐步验证，不做一次性重构。

## Qwen 对齐器使用已安装的本地快照

Qwen 强制对齐不依赖运行时访问 Hugging Face。worker 启动前强制离线环境，模型仓库名只解析本地缓存，实际加载传入快照目录。Qwen 库内部的 processor 加载不会继承模型的 `local_files_only`，因此仅给外层调用加参数不足以阻止联网；目录加载与离线环境共同覆盖两条路径。缺缓存或文件损坏时明确失败，由部署者预先补齐文件，不静默下载或切换模型。

## BililiveTool 是唯一的 B 站上传边界

Folia 只在成片后生成投稿文案、封面和 BililiveTool payload，不实现 B 站登录、Cookie、分片上传、断点续传或投稿 API。Phase 1 只读 preset 并校验参数，固定停在 `ready`。歌曲身份只能来自 `identified_*` 字段。视频与封面通过共享挂载传路径，不复制大文件。上传属于独立的下游状态机，失败不得回滚或污染 ASR、切歌、歌词和渲染结果。

每条自动化主播规则显式锁定投稿主播显示名和 BililiveTool 视频 preset。页面实时读取 BililiveTool 的 preset 列表供选择；创建投稿任务时把选择结果一起快照，避免全局默认值变更影响不同主播。旧规则未选择模板时不创建投稿准备任务，不能静默套用另一主播的全局默认 preset；常驻对账只按持久化水位处理之后完成的成片，所以未选模板期间完成的成片不会在选好后自动补建，如需补建须另行确认。投稿简介由所选 preset 的 `config.desc` 管理，并调用 BililiveTool 自身的 `formatDesc` 展开日期等变量；只有 preset 简介为空时才使用 Folia 固定简介。已经持久化的 payload 不随规则或 preset 后续变化而改写。

## 投稿素材按锁定主播管理，不设公共兜底

投稿模板、封面底图和封面标题字体集中在“投稿管理”页，按自动流水线锁定的主播规则（规则 ID，随录播机身份跟随改名）分别设置；流水线规则表单不再选择模板，新建规则的模板为空，直到在投稿管理页选择。封面底图存于 `data/cover-templates/<规则 ID>/`，复用图片库的解码校验与按内容去重。某主播没有底图时准备任务明确失败并提示去上传，不从公共池或其他主播借图，避免把一位主播的封面用于另一位主播；上传后可在页面重试。封面字体可选内置思源黑体/宋体（使用简体中文字形）或字体库中的上传字体，保存前实际加载校验。字体库与歌词效果共用，删除上传字体前检查歌词项目样式、流水线规则样式和封面设置，仍在使用则拒绝删除；内置字体不可删除。删除封面底图不影响已经生成并冻结在 payload 里的封面文件。

## 人工修正歌曲信息与自动识别分开保存

制作页允许用户明确修改歌名和歌手。显示值写入项目 `title`、`artist`，人工搜索优先值写入 `manual_title`、`manual_artist`；原自动识别值继续保存在 `identified_title`、`identified_artist`。普通歌词候选仍不能改写歌曲身份。这样用户的明确修正可用于下一次自动匹配和成片信息，同时保留识别记录，后续指纹结果也不会覆盖人工显示值或重命名源切片。

## Tempera 图片沿用官方资产契约

视频工坊的图片接入 Folia v0.7.8 官方 Tempera 图片池。每个项目拥有独立图片库，项目样式只保留图片 ID 与官方摆放参数；原图经校验、缩放后按内容存入 NAS 的项目目录，预览和原生导出从同源 `/images/<项目 ID>/<图片 ID>` 取图，并向 OBS 配置同时提供 `layerImages` 与 `temperaLayerImageAssets`。「从本片移出」只改变使用状态，「删除」从当前项目永久移除素材及已保存引用。图片作为透明特效层覆盖录播，整屏背景模式暂不开放。这样可以保持既有三种导出与原视频画面，不必改固定上游源码。

- 2026-09-20：音频指纹不再拥有不可推翻的歌曲身份。初次识别保留“首个命中即停”的低成本路径；只有歌词初选低置信时才继续扫描 ACRCloud，两个独立窗口同名才构成复查共识。同时允许严格门槛下的 ASR/歌词联合证据以 `evidence_consensus` 纠正错误指纹：初选低置信、挑战者高置信、核心锚点不少于 5、跨度不少于 10 秒、比分领先至少 40。普通歌词候选和人工选歌词仍不得写身份。

## CPU-only 是硬约束

目标机器为 Xeon E-2276M、16 GB 内存、Intel UHD 630，无 CUDA。所有核心功能必须可在 CPU 上运行，不能把 NVIDIA 或付费 API 设为必需条件。

## 实时渲染在 CPU 争用时优先

快速成片以 30 fps 实时录制浏览器画布；CPU 忙时丢失的视觉帧无法在封装阶段补回。转录服务可以延后完成，因此在 CPU 争用时给予原生渲染器更高权重、转录器更低权重，不暂停或重启正在处理的转录任务。x264 编码固定 4 线程，给同容器内的 Chromium 留出运行时间。较重视觉效果仍可选择透明逐帧输出换取稳定画面，不能宣称实时方式对所有效果都零卡帧。

## 流畅成片逐帧直出 MP4

实时录屏的速度与画面连续性互相牵制。需要流畅成片且不需要透明素材时，逐帧等待浏览器画面后截图，将透明歌词通过 FFmpeg 管道直接叠到原视频并编码 MP4。每帧由固定 30 fps 时间轴驱动，不受墙钟录屏速度限制；保留实时快速模式供追求速度的用户选择，保留 ProRes Alpha 模式供需要透明素材的用户选择。逐帧直出比实时模式慢，但避免为只要 MP4 的用户写入和再次读取体积很大的 ProRes 中间片。

## 工坊 UI 按工作区和屏宽重排

桌面以歌词预览/时间轴为宽主区，文件、效果和导出为侧栏。手机以固定底栏切换歌词制作、批量切片和自动流水线；歌词制作的四个步骤可独立展开，状态在浏览器会话中保存。转录页保留桌面入口及原页面，手机不显示其入口。前端只移动现有控件和改变呈现，不改变 API、项目数据、自动匹配或三种导出语义。自动流水线首次加载及返回保留内容的行为继续由原脚本控制。

## Whisper 与 Qwen 不同时常驻

16 GB 内存不足以稳妥常驻多个大模型。`local-worker` 在加载 Qwen 前卸载 Whisper，反向亦然，以启动时间换取稳定性。

## ASR 证据与标准时间轴是两种显式模式

- 旧项目和手工纯文本歌词继续使用 ASR 证据模式：ASR 决定字幕是否存在及其粗时间，标准歌词只纠正已识别片段中的错字和少量漏字，不能补入未识别整行。
- 用户主动执行“自动匹配标准时间轴”后进入新模式：ASR 只负责从多个有时间标准 LRC 中定位版本和一个全局偏移；不缩放、不逐句漂移，标准 LRC 的完整行结构决定字幕存在与固定行边界。
- 新模式必须至少存在一个歌词文字锚点。高置信需要 3 个以上锚点、跨度至少 10 秒且时间残差在门槛内；弱证据和无时间歌词估算必须明确标为低置信，零锚点直接失败且不得渲染。
- LRC 通常只有行起点：普通行终点取下一行起点；异常长间奏按该版本的典型行距结束上一行，不能让一行字幕覆盖整段无演唱区。
- Qwen ForcedAligner 只在旧的 ASR 证据模式中生成最终单字时间。标准时间轴模式中，Qwen 字时间只用于选择候选、计算一个全曲偏移和质量诊断，不能写回标准歌词的行或字。
- 对同音错字很多的旧模式演唱句，只能在已有近邻歌词锚点、下一行顺序和相近长度共同成立时降低字面匹配门槛；单凭标准歌词顺序不能在旧模式生成时间。

模型不能自行改写标准歌词。

## 标准逐字歌词只做一次全曲平移

标准歌词搜索通过独立 LDDC GPL 服务聚合 QQ、酷狗、网易云和 LRCLIB，主项目只经 HTTP 调用。候选选择仍以 ASR 文字、顺序和时间残差为主，不能因为带逐字时间就接受错误版本。

Qwen ForcedAligner 对歌曲片段生成的现场逐字结果用于与 LDDC 发行版逐字轴比较、选择版本、计算整体偏移并报告质量。选定标准逐字歌词后，最终每一行和每一个字都只采用平台原始时间加同一个偏移量。不得用 Qwen 时间替换标准歌词字符，不得逐行偏移或变形。

## 强制对齐按句执行

不把整场视频一次交给 Qwen。主 API 按已匹配的 ASR 片段提取短 WAV、逐句调用 worker，并在每句完成后持久化进度。这样既限制内存和搜索范围，也能显示真实进度，并让已完成结果在异常时得以保留。

## 分离流程暂时关闭

Demucs 在这台机器上曾因长音频和内存压力失败。当前优先验证原始混音 ASR 与标准歌词对齐；将来恢复分离时必须是可选、分块且经过峰值内存实测的独立模块。

## 批量切歌默认流复制

使用 FFmpeg `-c copy` 避免 4 GB 录播重新编码。优点是快、无代际损失；代价是起点可能受关键帧影响。需要帧级精度时应另设重编码模式，不能悄悄改变默认行为。

## 原录播不可变

原视频只读且永不覆盖。输出使用独立目录，重名自动追加编号。这一边界不能为了方便而放宽。

## 工坊缩略图与歌词时间条

缩略图只通过现有媒体文件 ID 定位只读视频，FFmpeg 在单线程后台队列中抽帧，图片缓存写入 `/data/thumbnails`；文件封面懒加载，选中视频的时间条使用最多 12 个固定位置，改变视口宽度仍复用这些位置。歌词时间条只显示项目已保存的 `alignment.lines`，未保存编辑不提前改变预览或成片。

自动流水线顶部统计必须由 SQLite 全量记录计算，不使用任务列表前 30 条推断；每日边界使用 `Asia/Shanghai`，完成数只计 `status=completed`。无任务时显示 0 与空状态。

## 工作台长列表按卡片独立滚动

用户确认文件、效果、歌词及任务等长内容应分别折叠和纵向滚动。桌面每张卡片独立折叠，手机保留原工作区步骤并让内部时间轴和长列表单独滚动；折叠与滚动只改显示，不改项目时间轴、效果参数或任务数据。文件列表图标列必须按实际图标宽度布局，避免文字覆盖图标。

## 成片只保留歌词首尾各五秒

完整成片以第一条和最后一条有效歌词为边界：开头最多保留 5 秒，结尾最多保留 5 秒；对应一侧空白不足 5 秒时不切，源视频不足时不补内容。平台署名行不参与边界计算。系统先正常完成字幕烧录，再对成品使用 `-c copy` 直接裁切，避免重新计算效果和二次编码；LRC 与输出时间轴同步归零，样片不套用这一规则。

## 自动流水线只让 AI 选择 ASR 句段

DeepSeek 可以判断哪里是完整歌曲及歌名，但不能提供系统采用的时间戳。模型只能引用已有逐句转录中的首尾 `segment_id`，后端再从本地 ASR 数据解析时间，避免模型编造边界。低于阈值、重叠和无效 ID 直接跳过。

整场录播按 180 秒块送现有 Faster-Whisper，禁用 VAD 与逐字计算，直接取得逐句时间供 DeepSeek 判歌；不再先对整场运行 Qwen ForcedAligner。歌曲切片复用并平移对应逐句文字，再仅对歌曲片段补 Qwen 现场逐字时间用于歌词匹配。断点须匹配 ASR 引擎和模型，不能把旧 Qwen 文本冒充 Whisper 逐句结果。所有主播共用串行队列，避免 16 GB CPU-only 机器上模型重叠。

## Fonia 原生视觉固定版本并与旧效果隔离

视频工坊新增的“Fonia 原生”固定使用 NAS 当前 Fonia 1.0.19 对应 revision `34e6d2258225610a178dde6ed1c406b699336c8a`，基础镜像同时固定到 digest。升级原 Fonia 播放器不得自动改变已保存项目的视觉。

旧“Folia 原版”、AMLL、Kinetic 和 ASS 渲染链保持原样。原生链只在 `style.effect=folia-native` 时启用，配置放在 `style.folia` 并记录 schema/revision。透明输出只关闭 Fonia 独立背景注册层，不通过删除 CSS 背景或跳过 visualizer 达成，以免破坏文字渐变和 Canvas/WebGL 特效。

原生导出固定 1080p30，并提供两个显式选择。默认“快速成片”让原视频与原生 visualizer 在 Xvfb 中实时合成，直接录制带原声音轨的 H.264 MP4；它不承诺 Alpha，目标是让 CPU-only NAS 的耗时接近片长。需要复用透明歌词层时选择“透明歌词 MOV + MP4”，继续逐帧生成无声 ProRes 4444 Alpha MOV，再叠回原视频；透明 MOV 是可复用母版，不因 MP4 合成成功而删除。两条链使用不同文件名，互不覆盖，也不得为了加速而降低或替换 visualizer 特效。第一版不接收自定义字体、头像、贴图或表情资源，只开放主题、缩放、透明度和原生 tuning JSON。


## 2026-09-26 主播改名联动

工坊按录播机的平台＋房间号锁定主播，名字只作显示。只读 bililive-tools 数据库记录取得实际录播目录，保留已知旧目录并自动发现新目录；不改录播机文件命名，不移动原录播，不通过前缀或模糊名称匹配身份。数据库暂不可读时使用持久化身份与历史目录继续监听。


## 2026-09-26：新视频放第二块硬盘，应用数据与旧文件留原处

用户确定只迁移今后的录播、切片和成片保存位置，不迁移应用或工作数据。采用新 RW / 旧 RO 的统一媒体视图，保留项目相对路径和录播工具历史 `/app/video` 路径；成片写入新根目录，历史文件按原项目输出路径回读旧根目录。旧文件不复制、不移动，不让符号链接绕开媒体安全路径校验。目录挂载必须在 Docker 启动前就绪；切换录播容器须先收尾正在录制的文件。
